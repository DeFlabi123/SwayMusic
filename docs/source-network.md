## Source architecture and mapping

`innertube/.../YouTube.kt` is the parsed service facade: song search uses `WEB_REMIX`, filter `EgWKAQIIAWoKEAkQBRAKEAMQBA%3D%3D`; search continuation sends the continuation token. Home uses `FEmusic_home`, playlist pages use `VL` browse IDs, and radio uses next/watch queue endpoints. `pages/SearchPage.kt` resolves video identifiers from playlistItemData, navigation/watch endpoints, overlay play buttons, and first flex-column runs. Artist and album links are distinguished by browse page type. Durations are parsed from secondary/fixed columns. This behavior is adapted in `YouTubeMusicClient` rather than copying Android UI/view model machinery.

`innertube/.../InnerTube.kt` is now a compatibility facade around external `com.github.MetrolistGroup.innertubex` **v0.11.2** (`gradle/libs.versions.toml`). The complete HTTP/session/cipher implementation is therefore not in the supplied original repository. It owns `locale`, `visitorData`, `dataSyncId`, `authUser`, cookies, proxy configuration and authenticated requests. Its Android transport reuses OkHttp connections, compresses responses and uses endpoint-specific transient retries. The desktop client similarly shares the caller's HttpClient, streams bounded JSON, sends locale/visitor data, retries transient HTTP failures at most twice, and propagates cancellation.

Desktop Google sign-in uses an explicit temporary instance of installed Edge/Chrome, then validates the resulting session through `account/account_menu` before saving it. Advanced manual Cookie-header import remains for compatibility. SAPISID-family authentication signs the request timestamp, matching cookie and music.youtube.com origin. Session cookies are used only on that service endpoint. The selected browser account index, visitor data and data-sync identifier accompany authenticated requests and are preserved with confirmed identity in the DPAPI account envelope. No app password collection or embedded browser is used. Native multi-account/channel selection, automatic session refresh and cloud playlist mutations remain incomplete. See [authentication.md](authentication.md) for the browser lifecycle and verification boundary.

## Playback extraction and desktop replacement

`app/.../utils/InnerTubeXPlayer.kt` is the sole Android stream extraction entry point. It builds InnerTubeX's config store, cipher service and extractor; feeds network/audio quality and upload hints; and retries alternate clients when a signed URL is rejected. The source explicitly disables HLS and SABR for its playback engine. Android BotGuard tokens are generated through a WebView provider (`utils/potoken`), which conflicts with this port's runtime requirements. That provider was not copied.

The desktop client first requests the actual player response, selects only HTTPS googlevideo-hosted AAC/MP4 audio and validates the URL with a bounded range request and an actual media-byte read. It never pretends a ciphered URL is usable. A separately supplied native `tools/yt-dlp.exe` plus `tools/qjs.exe` can resolve YouTube's changing signature challenges on demand. No process stays active between resolutions. The executable is run with isolated arguments (`--ignore-config`, no persistent cache), bounded output, a deadline and process-tree cancellation. Neither command lines nor errors expose cookies or signed URLs. This is a deliberate desktop replacement for Android's extraction dependencies, not a Kotlin algorithm translation.

Signed stream URLs are cached in a bounded 24-entry cache, expire two minutes before the server deadline, and are invalidated when the account cookie changes. A resolution gate prevents simultaneous player/download requests for one track from invoking redundant extractors. Compressed audio is exposed through `HttpRangeStream`, which reuses a shared HttpClient and one 256 KiB payload buffer. A 30-second deadline covers both headers and body for each range; document responses, changing lengths and truncated ranges fail explicitly. Cancellation and on-demand forward/backward seeks avoid opaque native HTTP behavior and full-file buffering.

YouTube's AAC stream is commonly fragmented DASH MP4. A retained real media file returned immediate end-of-stream without PCM from the Windows MP4 demuxer even when read locally; changing HTTP readers could not fix that format incompatibility. The playback layer therefore adapts the existing compressed AAC packets to a virtual ADTS stream, leaving decoding to Windows. Container metadata is read through exact sparse `ReadRangeAsync` requests without disturbing the payload cursor or its current chunk. Four concurrent metadata reads build the seek index without fetching every segment's audio. This is a packet/container adaptation, not transcoding or loading the entire file into memory. The final transport remains direct and demand-driven rather than running a local HTTP server.

Primary upstream references: [InnerTubeX](https://github.com/MetrolistGroup/innertubex), [yt-dlp YouTube client profiles](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/youtube/_base.py), [yt-dlp JavaScript runtimes](https://github.com/yt-dlp/yt-dlp/wiki/EJS).

## Validation and remaining scope

`NetworkTests` exercises source-shaped renderer parsing, deduplication, endpoint metadata, duration, continuation, authentication header construction, locale requests, cancellation, transient retry, hostile/ciphered URL rejection, bounded signed URL caching and account invalidation. Its byte-pattern transport fixture checks forward/backward range seeks, EOF, request counts and the 256 KiB upper bound. `AccountNetworkTests` covers account-menu confirmation, selected-account headers/context, expired and malformed responses, response limits and cancellation. `LiveAsync` is an opt-in real search, continuation, home, browse, radio, resolved-media and muted native stream playback check; its outcome must be recorded by the caller. Offline fixtures prove parser behavior, not remote service availability. Authenticated extraction cookies, region-specific restrictions, a native brand-account picker, cloud playlist mutations, upload playback, podcasts beyond generic watch renderers, download URL refresh after expiry, and automatic extractor updates remain incomplete or unverified.

The final Google sign-in integration passed account/browser fixtures and headless account UI/race/lifecycle checks. Installed Microsoft Edge 157 passed an actual blank-page CDP-pipe transport and process/profile cleanup smoke in 1.10 seconds. The full deterministic/native/live run passed in 56.11 seconds (56.50 seconds wall time): real AAC played for 25.71 seconds, pause stopped upstream reads, seek/resume/stop passed, and a real 1,890,654-byte ranged download decoded offline without network resolution. Completing a personal Google account sign-in/MFA remains a manual check; these tests do not claim it.

### Previous baseline: 2026-11-10

On 2026-11-10 the stable .NET 10.0.404 build passed with zero warnings/errors. Live search, search continuation, Home, playlist browse and radio requests passed. A real 2:34 YouTube Music AAC track played through the production virtual-ADTS/native Media Foundation/WASAPI path for 25 seconds with an advancing clock; pause, seek, resume and stop passed. During a two-second paused interval, upstream bytes did not increase. Only 581,632 bytes of the 2,484,584-byte source were fetched during that playback, including sparse indexing metadata. This verifies demand-driven streaming rather than downloading the entire recording before playback. These are observed checks on this network/host, not a guarantee that every restricted track or future service revision will work.

That baseline integrated `--audio --live` run also downloaded the complete 2,484,584-byte recording through the production range-based DownloadService, verified its atomic file/manifest commit, and played the saved fragmented AAC offline through the native decoder. The offline resolver deliberately threw if invoked: local decoding, pause, seek to ten seconds, resume and stop still passed without resolving any remote URL. The full offline/native/live test run returned exit code zero in 50.22 seconds. Test media and temporary download manifests are not included in the distributed application or source archive.
