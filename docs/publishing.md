# Publishing SwayMusic

Installer releases and signed in-app updates are documented in [updates.md](updates.md). Run `pwsh -File scripts/Pack-Release.ps1 -Version 1.0.0` to package the self-contained payload into `artifacts/installer`. The GitHub workflow performs this for version tags and creates a draft release. Configure `UPDATE_SIGNING_PRIVATE_KEY` before running it; Windows Authenticode signing is configured separately. Local development installers can be unsigned by Windows while retaining authenticated update metadata.

The application targets stable .NET 10, Windows x64. The single release directory is `artifacts/SwayMusic-win-x64`; it includes CoreCLR, native Skia/HarfBuzz, WinRT projections and the native on-demand stream helpers. It requires no Java or embedded browser frontend.

The solution is `SwayMusic.slnx`, desktop project is `src/SwayMusic.Desktop/SwayMusic.Desktop.csproj`, and executable is `SwayMusic.exe`. Publish updates the same self-contained release folder and gracefully closes workspace SwayMusic instances before replacing locked binaries. It does not create alternate release folders or archives by default. Use `Publish.ps1 -Archive` or `Source-Archive.ps1` only when an archive is explicitly needed. Verify-Release rejects old Metrolist binaries and test assemblies. Historical source attribution is preserved in LICENSE/THIRD-PARTY-NOTICES.

Only Avalonia's Win32/Skia backend is referenced, rather than the cross-platform Desktop meta-package. Publishing with `win-x64` removes other-platform native assets. Only NAudio.Wasapi and Core are needed. Debug symbols are omitted from published builds; source and tests remain available separately. Workstation GC is selected to avoid server GC's per-CPU heap overhead for a single-user desktop application.

Native AOT is supported by Avalonia when the application and dependencies are compatible. It is not enabled here because this port currently uses reflection-based generic JSON persistence and NAudio/WinRT interop paths which need separate AOT verification. Compiled bindings, explicit composition and embedded resources already avoid several common obstacles. A next optimization pass should introduce source-generated JSON contexts, run AOT/trimming analyzers against all runtime dependencies, resolve warnings without suppressing unknown breakage, and rerun persistence, actual AAC decoding, SMTC and UI checks on the published output. Windows Native AOT also needs the C++ toolchain. See [Avalonia Native AOT guidance](https://docs.avaloniaui.net/docs/deployment/native-aot) and [Microsoft Native AOT requirements](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/).

`PublishReadyToRun` and single-file bundling are not presumed improvements: ReadyToRun increases installation size and should be compared against measured startup, while bundled native assets may add extraction work. This release uses normal Release compilation, ordinary native-library loading, no aggressive trimming, and no forced collections. A native Win32 fixture measured the production window and visible/minimized playback; results and limitations are recorded in PROGRESS.md. Software rendering was selected after a substantial private-memory reduction was measured. Native dependency PDBs are excluded by the publish target, saving roughly 100 MiB without removing executable code.

The host initially supplied only a usable preview SDK. On resuming development, the official portable stable .NET SDK 10.0.404 was downloaded, its Microsoft-published SHA512 verified, and extracted into `.sdk`. `global.json` now pins that stable feature band and rejects prerelease SDKs. Build/publish scripts prefer the local SDK and its runtime. `scripts/Install-DotNet.ps1` can reproduce the installation from Microsoft's channel metadata without machine-wide changes.

Both distributions must include LICENSE, THIRD-PARTY-NOTICES, the helper licenses and corresponding application source under GPL-3.0. The helper download script pins exact upstream versions and SHA256 hashes; helper changes are reviewed and delivered together with a publisher-verified application release. Velopack's MIT license is included in licenses.

`scripts/Verify-Release.ps1` starts the actual published executable in its isolated verification mode, which constructs the production native window, saves a runtime/architecture report and closes itself after three seconds. Its temporary library is separate from the user's data. Final SwayMusic self-contained verification deliberately used nonexistent DOTNET_ROOT and DOTNET_ROOT_X64 paths and successfully loaded the bundled .NET 10.0.15 runtime. The framework-dependent executable passed against the verified local .NET 10.0.15 x64 runtime. Both reported clean close and X64; the JSON reports are in `docs/verification-self-contained.json` and `docs/verification-framework-dependent.json`. This checks the distribution layout and entry point in addition to the control/engine tests.
